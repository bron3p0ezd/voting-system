# AGENTS.md

## Область действия

- Эти инструкции действуют для всего репозитория `backend`.
- `AGENTS.md` содержит только постоянные правила проекта. Пошаговые сценарии находятся в `.agents/skills/`.
- Вложенный `AGENTS.md` дополняет этот файл в пределах своего каталога; более узкое правило имеет приоритет.
- Для файлов в `src/tests/` дополнительно применяй `src/tests/AGENTS.md`.

## Проект

- Стек: Python 3.13, FastAPI 0.115, SQLAlchemy 2.0 async, Pydantic 2, PostgreSQL/asyncpg, Alembic, pytest и pytest-asyncio.
- Исходный код находится в `src/`; точка входа — `src/main.py`; конфигурация — `src/config.py`.
- Домены находятся в `src/apps/`, инфраструктурные контракты и DI — в `src/settings/`.
- Локальная конфигурация читается из `src/envs/.env`.
- Не выводи в терминал, ответы или логи значения секретов из env-файлов.

### Текущее состояние реализации

В backend подготовлена базовая конфигурация FastAPI, описаны SQLAlchemy-модели
опросов и начальная Alembic-миграция для их создания. HTTP endpoints из корневого
контракта, сервисы и репозитории пока не реализованы.

Модель данных состоит из следующих таблиц:

| Таблица | Назначение |
|---|---|
| `polls` | Вопрос, тип выбора, допустимое число вариантов и период голосования |
| `poll_options` | Упорядоченные варианты ответа конкретного опроса |
| `votes` | Устойчиво учтённый факт участия с хешем технического ключа участника |
| `vote_selections` | Выбранные участником варианты; составной ключ запрещает повтор варианта |

Уникальность пары `poll_id` и `participant_key_hash` обеспечивает конкурентно
безопасную базовую дедупликацию на уровне базы данных. Это не строгая
идентификация человека: ограничение можно обойти очисткой cookie, сменой браузера
или устройства. IP-адрес в модели не используется.

Ограничения одной строки (временной интервал, диапазон числа выборов и правила
типа `single`) заданы в схеме базы данных. Сервис дополнительно проверяет минимум
два варианта, условие `max_selections <= options.length`, принадлежность вариантов
опросу и количество выбранных вариантов в одной транзакции.

## Запуск проекта

### Первичная подготовка в PowerShell

Выполняй команды из корня `backend` в указанном порядке:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
Set-Location src
..\.venv\Scripts\python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

Перед запуском заполни `src/envs/.env`. Обязательные параметры без безопасных значений по умолчанию определены в `src/config.py`. Не копируй секреты в `AGENTS.md`, skills или исходный код.

### Повторный локальный запуск

```powershell
.\.venv\Scripts\Activate.ps1
Set-Location src
..\.venv\Scripts\python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

- Локальный адрес: `http://127.0.0.1:8000/`.
- Health check: `http://127.0.0.1:8000/api/health`.
- OpenAPI endpoints зависят от `DOCS_URL_ENABLED`, `REDOC_URL_ENABLED` и `OPENAPI_URL_ENABLED`.
- Docker-сценарий также слушает порт `8000`; параметры production-запуска определены в `Dockerfile`.

Перед первым запуском приложения из каталога `backend` примени миграции:

```powershell
.\.venv\Scripts\python -m alembic upgrade head
```

Текущий слой моделей можно проверить без базы данных из каталога `backend\src`:

```powershell
..\.venv\Scripts\python -c "import migration_tables; from sqlalchemy.orm import configure_mappers; configure_mappers()"
```

Прикладные тесты пока не добавлены.

## Рабочий процесс

## Стиль и формат файлов

- Отвечай пользователю на русском языке.
- Сохраняй текстовые файлы в UTF-8 без BOM; исправляй mojibake в изменяемом файле.
- Не добавляй комментарии и docstrings, повторяющие очевидное поведение. Сохраняй необходимые framework-, lint- и type-checker-директивы.
- Соблюдай стиль существующего файла; не выполняй несвязанные форматирующие или архитектурные переработки.

## Python

- Типизируй аргументы и возвращаемые значения. Локальные переменные аннотируй, когда тип неочевиден или это помогает статической проверке.
- В новом коде используй встроенные generic-типы (`list`, `dict`, `set`, `tuple`) и синтаксис `T | None`.
- Используй из `typing` только действительно необходимые типы, например `Any`, `TypeVar`, `Generic`, `Protocol`, `cast`.
- Классы называй в единственном числе и `PascalCase`, функции и переменные — в `snake_case`. Имя файла должно отражать его основную ответственность.
- Соблюдай SRP. Разделяй построение данных, валидацию, I/O, обработку ошибок и преобразование результата, если у них разные причины для изменения.
- Для проектных функций и методов предпочитай не более трёх содержательных аргументов, не считая `self`/`cls`. Контракты фреймворков и существующие публичные интерфейсы — исключения.
- Лови конкретные исключения. Голые `except:` и необоснованные `except Exception:` запрещены.

## Импорты

- Используй абсолютные импорты от корня `src`, например `from apps.user.models import User` и `from settings.services import Service`.
- Размещай импорты вверху файла тремя группами: стандартная библиотека, внешние зависимости, локальные модули. Разделяй группы пустой строкой и сортируй внутри группы.
- Локальный импорт внутри функции допустим только для подтверждённого циклического импорта или monkeypatch в тесте.
- Удаляй неиспользуемые импорты.

## Архитектура домена

Сохраняй принятую структуру `src/apps/<domain>/`:

| Файл или каталог | Ответственность |
|---|---|
| `models.py` | SQLAlchemy ORM и enum модели |
| `dtos.py` | Межслойные и repository DTO |
| `schemas.py` | HTTP request/response схемы |
| `repositories.py` | Абстрактные контракты доступа к данным |
| `services.py`, `service.py` | Абстрактные бизнес-контракты |
| `db_services.py` | Опциональные контракты сервисов над repository |
| `routers.py`, `router.py` | FastAPI endpoints |
| `exceptions.py`, `policies.py` | Доменные ошибки и политики |
| `impls/` | Реализации контрактов |

- Не переименовывай исторически сложившиеся `service.py`/`router.py` только ради унификации.
- Контракты храни отдельно от реализаций. Реализации repository, service и db-service размещай в соответствующем подкаталоге `impls/` и называй с суффиксом `Impl`, если это принятый контракт проекта.
- Repository выполняет запросы и маппинг данных, но не содержит бизнес-логику и не делает `commit`/`rollback`.
- Service координирует сценарий, проверяет бизнес-правила и преобразует доменные ошибки. SQLAlchemy-запросы в service запрещены.
- DbService работает через repository API и считается частью сервисного слоя.
- Границу транзакции размещай на верхнем сервисном уровне: один `commit` после успешной последовательности изменений; при частичном изменении и ошибке — `rollback` и повторный `raise`.
- Router получает контракт сервиса через `ServiceFactory`, делегирует ему работу и возвращает результат. Не создавай реализации вручную и не помещай бизнес-логику в router.
- Подробные правила слоя загружай через соответствующий skill.

## Тестирование

- Для `src/tests/**` соблюдай вложенный `src/tests/AGENTS.md`.
- Запускай минимальный релевантный набор тестов из корня репозитория через `.venv`, например `.\.venv\Scripts\python -m pytest <path> -q`.
- Не создавай или не изменяй production-код только ради того, чтобы тест прошёл, если задача ограничена тестами.

## Skills

Skills находятся в `.agents/skills/` и загружаются только для релевантной задачи:

| Skill | Когда использовать |
|---|---|
| `$python-domain-architecture` | Новый домен, размещение кода или изменение межслойного сценария |
| `$python-models` | SQLAlchemy-модели, связи, enum, constraints |
| `$python-dtos` | DTO и HTTP request/response schemas |
| `$python-repositories` | Контракты и реализации доступа к данным |
| `$python-services` | Service, DbService, исключения и UOW |
| `$python-routers` | FastAPI endpoints, Depends и `ServiceFactory` |
| `$python-testing` | Pytest, fixtures, mock JSON и подготовка тестовой БД |

- Не загружай reference-файлы заранее; читай только те, на которые указывает активный workflow.
- Не дублируй подробную справку skill в `AGENTS.md`.
